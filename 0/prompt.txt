There's another CI improvement I'd like to consider: in personal and cluster CI the user triggers a CI check manually. These checks, presently, take 2-3 hours. However it is very unfortunate if one triggers a check for a candidate ref (especially a PR) without realizing that the baseline ref (typically main) is ahead of the candidate ref (e.g. main has not been merged into the PR branch). What options do we have to we prevent this scenario, so that the user doesn't waste 2-3 hours by running CI comparing two refs where the baseline hasn't been merged into the candidate?
