The current branch (gk_adiab_elc_2x3v-api_changes) implements an adiabatic electron model, where the electron density is n_e(t) = n_e(t=0) * (1 + e(phi-<phi>_{fsa})/T_e(t=0), and < >_{fsa} means a flux surface average and phi = phi(t) is the potential.

One issue with this work is that although it only needs the electron density and temperature, which are user inputs, we still need to initialize a whole distribution function in order to take moments of it. This is problematic because it takes up a lot more memory than needed, and the accuracy of the discrete density and temperature depend on our velocity grid extents, mapping and number of cells.

I'd like to instead implement a fluid gk_species option, much like gk_neut_species allows for either kinetic of fluid neutrals. Thinking from the top down, starting from the input file, I would like the electron table in an input file like gyrokinetic/creg/rt_gk_cbc_adiabatic_3x2v_p1.c to instead look like

struct gkyl_gyrokinetic_species elc = {
  .name = "elc",
  .charge = ctx.qe,
  .mass = ctx.me,
  .projection =
    {
      .proj_id = GKYL_PROJ_MAXWELLIAN_PRIM,
      .density = eval_dens_ic, // Match the ion equilibrium density.

      .upar = eval_upar_elc_ic,
      .ctx_upar = &ctx,
      .temp = eval_temp_elc_ic,
      .ctx_temp = &ctx,
    },
  .scaling = {.type = GKYL_GK_SPECIES_SCALING_ADIABATIC},
  .num_diag_moments = 1,
  .diag_moments = {GKYL_F_MOMENT_M0},
};

That is, to ommit lower, upper and cells. When this happens, gk_species will deflect many of its methods to a gk_species_fluid (and many of the present methods will move to gk_species_kinetic), where it'll initialize moments without allocating a phase-space distribution function. Other methods need to adapt accordingly. For example, gk_species_moment and gk_species_projection need to have support for a fluid species, so that other modules can simply ask for moments or projections without caring if the species is fluid or kinetic (in the fluid case gk_species_projection would actually project moments, not distributions).

You can examine how this works in gk_neut_species.
